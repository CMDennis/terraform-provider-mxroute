# mxroute Provider

MXroute all-operation beta candidate. Requires Terraform >= 1.11.1, < 2.0. Domains, pointers, mailboxes, routing, shared spam controls, usage reporting, DNS discovery, reseller packages/users and impersonation aliases are mock-tested; live behavior remains unverified. Credentials are kept only in memory; use environment variables or ephemeral inputs to avoid saving them in configuration or plans.

This beta candidate provides ten resources for domains, pointers, mailboxes,
routing, shared spam controls, reseller packages and reseller users, with twenty
data sources including quota, per-email usage and reseller inventories. Every one
of the 43 documented API operations has a Terraform workflow. See
[reseller packages, users and impersonation](../examples/reseller/README.md) for
plain versus impersonated providers, staged applies, units and update ordering.
See [shared spam and reporting](../examples/spam/README.md) for
account ownership, imports and hourly snapshot limitations. See
[domain onboarding](../examples/onboarding/README.md) for the verification and DNS workflow. It has not been published to the Terraform Registry.
Phase 7 verified all fourteen ordinary-account read operations without writes;
the settings baseline was unchanged. A later authorized test created one new
mailbox, updated only its quota/send limit/password, and verified live import plus
a no-change plan in separate protected state. A later explicitly authorized cleanup removed it;
the original inventory/configuration was restored. See [mailbox test scope](design/mailbox-live-testing.md).
Other live mutations, reseller operations and impersonation remain unverified. See
[validation and limits](design/phase7.md), [adopting existing objects](design/migration.md)
and [troubleshooting](design/troubleshooting.md). Offline lifecycle success is not
proof of live write compatibility. Authenticated tests require authorization under
the account-protection policy; the normal test suite uses synthetic local mocks.

## Authentication

Supply `MXROUTE_SERVER`, `MXROUTE_USERNAME`, and `MXROUTE_API_KEY` at runtime.
Explicit configuration wins; an explicit empty string is an error. Unknown values
are allowed during validation and must resolve before provider configuration.
The endpoint is fixed to `https://api.mxroute.com`. There is no endpoint setting
or endpoint environment fallback. Provider configuration performs no requests.

Use the complete API key unchanged, including colons. Account-password authentication requires DirectAdmin to permit it
(`api_with_password=yes`); login keys are unaffected by that setting. Key
restrictions must permit the requested operations, session queries, and
impersonation when used. Reseller impersonation uses
`reseller|user` with the reseller's own key. Reseller-only operations require a
plain reseller configuration. Use provider aliases for independent accounts.

`sensitive` hides display; it does not prevent persistence of literal values or
ordinary input variables in saved plans. Prefer runtime environment credentials
or ephemeral variables. Never put secrets or real account identifiers in Git.
Mailbox and reseller-user passwords use `password_wo` with a positive `password_wo_version`.
Supply an ephemeral password on creation and increase the version for rotation.
Import and updates with an unchanged version require no password. Passwords
are never returned by reads. See [mail configuration](../examples/mail/README.md)
for rotation, import, routing interruption and catch-all relinquish semantics.

## Example Usage

```terraform
terraform {
  required_version = ">= 1.11.1, < 2.0.0"
  required_providers {
    mxroute = {
      source = "cmdennis/mxroute"
    }
  }
}

# Supply MXROUTE_SERVER, MXROUTE_USERNAME and MXROUTE_API_KEY at runtime.
# This address requires a local development override until publication.
provider "mxroute" {}
```

See `examples/aliases/provider.tf` for an impersonated alias using an ephemeral
API key input. Use local development overrides or a filesystem mirror until a
release is published; no Registry installation is available today.
